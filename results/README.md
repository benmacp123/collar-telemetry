# Results

Everything here is generated by a `make` target from committed inputs;
runs are seeded and reproduce byte for byte. Do not edit by hand.

| Path | What it is | Made by |
|---|---|---|
| `replay/<study>/<scenario>/summary.json` | Settings, cleaner and lifecycle drop counts, and incident counts for one replay | `make replay` |
| `replay/storks-<population>/...` | The same for the white stork tuning populations (`storks-sw-germany`, `storks-bavaria`), from the hourly extract. The three held-out populations are never replayed by this target, and `--study` refuses them | `make replay` |
| `replay/<study>/<scenario>/incidents.jsonl` | Every incident from that replay (not committed; regenerated) | `make replay` |
| `replay/<variant>/deaths.json` | What was injected into a synthetic variant (`jackals-synthetic`, `elephants-synthetic`): per synthetic deployment, its real source, carcass regime, death time and position, and carcass fix count | `make replay` |
| `evaluation/<variant>-all.json` | A synthetic variant's deaths scored by carcass regime and pooled, from the computed death start and the injected time | `make evaluate` |
| `evaluation/<study>-<set>.json` | Detection rate, delay and operator load against known outcomes, per scenario. Vultures are split into `tuning` (thresholds chosen) and `scoring` (held out); mammals are scored as `all`. `vultures-scoring.json` is rewritten only by `make score`; other runs read it back unchanged | `make evaluate`; `make score` for `vultures-scoring.json` |
| `LOOKS.md` | Every time the held-out vulture set has been scored or seen: date, commit, reason and headline figures. Entries up to 2026-10-24 are reconstructed from the commit trail | `make score` appends one entry |
| `evaluation/EVALUATION.md` | The evaluation tables, with definitions, each split set's figures against the targets in `config/experiment.toml` and the base-rate ceiling beside them | `make evaluate` |
| `sweep/vultures-tuning.json`, `sweep/SWEEP.md` | Mortality window, box and gap margin swept on the vulture tuning set; the grid comes from `config/experiment.toml`, and each setting is shown against its watch targets and ceiling; the black-vulture window is also swept on its own, with the decision rule's outcome (figure `figures/sweep-vultures-tuning-species.png`) | `make sweep` |
| `stillness/stillness.json`, `stillness/STILLNESS.md` | How often living animals stay still past 12 h to a week, under the mortality detector's own cluster rule: vulture tuning set (by species; every tuning tag is Argos PTT), every jackal and elephant, and the two stork tuning populations (by tag model; deaths from the end type alone until labels are reviewed), with the vulture carcass periods beside them | `make stillness` |
| `bouts/bouts.json`, `bouts/BOUTS.md` | Every living still bout of the stork tuning populations longer than the mortality window, put in one of seven classes by when and where it happened and how often the tag was fixing (nestling, sparse fixes, back at the natal nest, a site used over several years in or out of the breeding season, a site used in one year, one-off): bouts, birds, the largest share one bird holds, bouts past 72 h and a week, and the median acceleration spread per class (figure `figures/bouts-classes.png`). The class cut-offs are in `config/experiment.toml` under `[descriptive.still_bouts]`, chosen by eye on these populations: descriptive, used by no detector | `make bouts` |
| `fledging/fledging.json`, `fledging/FLEDGING.md` | Stork tuning populations split at each bird's first fix beyond 500 m (and 2 km) from where its tag started: days to leave, and stationary, potential-death and gap alerts and tracked time on each side, under GSM uploads. Counts every alert, true or false; no outcome labels | `make fledging` (after `make replay`) |
| `acceleration/acceleration.json`, `acceleration/ACCELERATION.md` | Stork acceleration cue (median hourly burst spread over the 24 h before a watch alert, defined in the experiment file before the fit): share of true and false watch alerts passing at each threshold, the likelihood ratio, and the frozen rule's operating point. Stork tuning populations only; deaths graded `acc-inferred` left out | `make acceleration` (after `make replay`) |
| `fixrate/fixrate.json`, `fixrate/FIXRATE.md` | Fix-rate cue (rate since the stationary run began over the rate in the days before): the eight variants, each at the lowest cut keeping half the true watch alerts, vultures and storks weighted equally, and the chosen definition. Tuning birds only; deaths graded `acc-inferred` left out | `make fixrate` (after `make replay`) |
| `departure/departure.json`, `departure/DEPARTURE.md` | How the mortality detector decides a still tag has moved again: the box-only detector against bigger boxes, three leave fixes, longer merge windows and a leaving radius, on the vulture tuning set and on mammal variants drawn with a separate tuning seed (2027); flapped, split and ended-resolved deaths, false-alert load and duration, detection by the mark | `make departure` |
| `carcass/carcass.json` | How collars behave on the vulture tuning set's carcass deaths (rate of new positions against the live rate, two regimes, scatter without repeated positions), each study's share of repeated positions and the mammals' still-window scatter; the synthetic mortality defaults must match it | `make carcass` |
| `cloud/sizing.json` | The cloud runner's daily slices run locally: message and state sizes, modelled state table write units for the stored layout and the first deployed one, and a check that the incidents match the replay | `make cloud-sizing` |
| `cloud/local-moto.json` | Every study under `satellite_daily` and `gsm` sent through the cloud handlers on in-process moto, with resends: message counts, and checks that the stored incidents match the replay and that each `potential_death` incident sent one notification | `make cloud-moto` |
| `cloud/local-docker.json` | The same for every jackal and one vulture, with the handlers in Lambda containers | `make cloud-local` |
| `cloud/aws-<label>.json` | Runs on the deployed AWS stack (`smoke`: every jackal, with resends; `email`: one vulture with notification on; `full`: every study under `satellite_daily` and `gsm`): checks against the replay, dead letters, wall-clock latencies and the run's time window. Needs an AWS account, so not reproducible from a clone; the local files above check the same handlers without one | `make tf-apply`, then `make cloud-aws ARGS=...` |
| `cloud/aws-clock.json` | One invocation of the live clock on the deployed stack: a tick to every jackal collar, drained with no dead letter. Needs an AWS account | `make cloud-clock` |
| `cloud/usage-aws.json` | Per-minute CloudWatch sums for the deployed stack's functions, queue, tables, log groups and topic over the deploy day: resource names and counts, no account details. Needs an AWS account to fetch; committed so the cost report reproduces without one | `make cloud-usage` |
| `cloud/usage-aws-2026-10-22.json` | The same for 22 October, both deploy sessions, restored from the file's history so the bill check needs no git history | `make cloud-usage` at the time |
| `cloud/billed-aws.json` | What AWS billed on the two deploy days, line by line, and the project's services' cost afterwards: no account details. A hand-run Cost Explorer query, recorded in the file; `tests/cloud/test_cost.py` compares it with the metered usage | Not a `make` target |
| `cloud/cost.json`, `cloud/COST.md` | The full run's bill at the committed list prices (`data/prices/`), cost per animal-month, a provisional live-mode projection, idle polling cost and free-tier headroom | `make cloud-cost` |
| `figures/` | PNG figures used in the README and reports; `vultures-death-timeline.png` follows one tuning-set death (LET_TUVU_68355) under ideal arrival and daily satellite uploads | `make evaluate`, `make sweep`, `make stillness`, `make bouts` |

Scenarios are the simulated upload patterns (`ideal`, `satellite_daily`,
`satellite_2day`, `gsm`), described in `src/telemetry/sim/arrival.py`.
Every threshold and its source is in
[`docs/ASSUMPTIONS.md`](../docs/ASSUMPTIONS.md).
